## Реализация FoodExpress — Никита Ригун

СУБД: PostgreSQL 15.
Рабочая схема: `rigun_food`.

SQL-скрипты находятся в `db/schema/`.

Резервная копия: `db/foodexpress_rigun.backup`.

Документация:
- `db/constraints.md` — ограничения базы данных.
- `db/tests.md` — результаты тестирования.

Для восстановления архива необходимо заранее обеспечить
доступность `exts.uuid_generate_v4()` (расширение uuid-ossp
в схеме exts).

Для проверки используются процедуры `insert_test_data`,
`erase_test_data`, `add_product`, `courier_salary`,
функция `get_statistic` и представление `how_much_money`.

### Восстановление на другом сервере

В целевой базе предварительно должны существовать схема `exts` и расширение `uuid-ossp`.
Не требуется создавать роль `rigun` из исходного сервера. Запуск восстановления:

```bash
pg_restore --no-owner --no-acl --exit-on-error -d <имя_базы> db/foodexpress_rigun.backup
```

Для роли `inspector` администратор целевой базы применяет `db/schema/grants.sql`.
Для развёртывания по SQL на чистой базе сначала подготовить `exts`, затем выполнить
скрипты `01_types.sql`–`14_audit_fixes.sql` в числовом порядке (кроме grants.sql).


### Дополнение к установке: миграции 15–16 и актуальный архив

При развёртывании базы **из SQL-файлов** применяйте все скрипты `db/schema/01_types.sql` … `db/schema/16_truncate_guards.sql` по порядку (включая `14_audit_fixes.sql`, `15_final_audit_fixes.sql` и `16_truncate_guards.sql`). Скрипт `grants.sql` выполняется после создания объектов.

При развёртывании **из актуального** `db/foodexpress_rigun.backup` повторно запускать миграции 01–16 не нужно: они уже включены в архив. Для переноса между кластерами используйте `pg_restore --no-owner --no-acl` и заранее подготовьте требуемое расширение `uuid-ossp` в схеме `exts`, как описано выше. Перед сдачей пересоздайте архив из обновлённой базы и проверьте восстановление в отдельной тестовой базе.

**Примечание:** упоминания скриптов 01–14 выше относятся к предыдущему этапу; актуальная последовательность — 01–16.
